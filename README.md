# Mac power monitor

Local MacBook charging reminders delivered to Samuel's Telegram bot. No AI,
Codex automation, or always-on external server is involved.

## What it does

- Checks every 15 seconds through a macOS LaunchAgent.
- While unplugged, sends an alert after 30 seconds locked, or when battery is
  at or below 10% and the Mac is locked or idle for at least 30 seconds.
- Attempts an immediate alert before system sleep, including lid-close sleep.
  Message delivery has a four-second timeout.
- Reacts with 👍 to the latest alert when AC power returns.
- Keeps one unresolved alert until power is connected. Unlocking or waking does
  not reset it. A process lock prevents concurrent checks from duplicating it.
- Randomly selects one of ten casual Slovak messages for each of the three
  alert categories. These are static strings, not generated by a model.

## Files and implementation

| File | Purpose |
| --- | --- |
| `monitor.zsh` | Reads `pmset` battery/power state and `ioreg` lock/idle state; sends alerts and reactions through Telegram's Bot API. |
| `sleep-listener.c` | IOKit/CoreFoundation process that invokes the adjacent monitor before sleep and on power-source changes. |
| `launchagents/` | LaunchAgent templates: a 15-second checker and a persistent listener. |
| `configure-telegram.zsh` | Interactive bot setup; stores credentials in macOS Keychain and sends a test message. |
| `send-telegram` | Python command for arbitrary messages; accepts arguments or stdin and splits long messages into 4,000-character chunks. |

The monitor writes `.state` and `.lock` beside its installed script. State
contains the lock timestamp and the unresolved Telegram message ID. Neither
runtime state nor compiled binaries belong in Git.

## Where it actually runs

On 2026-10-08, this code was recovered from
[`samochreno/mac-setup`](https://github.com/samochreno/mac-setup), under
`macos/services/power-monitor/`. The installed monitor matched that source.
The original July chat used a different installation directory, which was
subsequently replaced by the mac-setup location.

Current installation:

```text
~/Library/Application Support/mac-setup/services/power-monitor/monitor.zsh
~/Library/Application Support/mac-setup/services/power-monitor/sleep-listener
~/Library/LaunchAgents/com.samochreno.macbook-power-monitor.plist
~/Library/LaunchAgents/com.samochreno.macbook-power-sleep-listener.plist
~/Library/Logs/mac-setup/macbook-power-monitor.log
~/Library/Logs/mac-setup/macbook-power-sleep-listener.log
~/.local/bin/send-telegram
```

This repository preserves the current implementation. Creating it did not
reinstall or restart the services. Future mac-setup service installations can
overwrite the installed monitor; account for that when deploying changes here.
The standalone sender also has its own
[`send-telegram` repository](https://github.com/samochreno/send-telegram).

## Sleep limitations

Nothing executes during full system sleep. The listener handles the brief
window before sleep and power-source events while the Mac can execute code.
USB-C connection may cause a DarkWake, but delivery during that window is not
guaranteed. Disconnecting power during deep sleep may not wake the Mac at all.

The recovered listener subscribes to power-source changes; it does **not** have
a `kIOMessageSystemHasPoweredOn` callback. The older chat described an explicit
wake callback, so its description is not identical to this later implementation.
Pre-sleep notifications apply to system sleep generally, not exclusively lid
closure, even though some message variations mention a closed lid.

## Requirements and credentials

macOS on a MacBook, Command Line Tools (`xcode-select --install`), and `jq`.
The monitor and setup look for `jq` at `/opt/homebrew/bin/jq`, then `/usr/bin/jq`.
Python 3 is needed for `send-telegram` and the restore instructions below.

Both monitor commands retrieve these Keychain items for the current username:

- `codex-power-monitor-telegram-token`
- `codex-power-monitor-telegram-chat-id`

Credentials are deliberately absent from this repository. Existing Keychain
items continue to work. To configure a new bot, privately create it through
Telegram's @BotFather, open its chat, press Start and send a message, then run:

```zsh
./configure-telegram.zsh
```

Token input is hidden. Setup chooses the last chat found in the bot's updates,
so use a dedicated bot and do not add it to other chats before setup.

The standalone `send-telegram` additionally supports `TELEGRAM_BOT_TOKEN` and
`TELEGRAM_CHAT_ID` environment variables, then protected files under
`${XDG_CONFIG_HOME:-~/.config}/send-telegram/{bot-token,chat-id}`. The monitor
itself only uses Keychain.

## Restore or deploy from this repository

Run from the repository root. These commands replace the existing two monitor
jobs using their current names and paths; they preserve `.state` and Keychain
items. They do not install any other mac-setup services.

First build and copy the programs:

```zsh
support_dir="$HOME/Library/Application Support/mac-setup/services/power-monitor"
mkdir -p "$support_dir" "$HOME/Library/Logs/mac-setup" "$HOME/Library/LaunchAgents"
xcrun clang -Wall -Wextra -Werror -framework CoreFoundation -framework IOKit \
  sleep-listener.c -o "$support_dir/sleep-listener"
install -m 755 monitor.zsh "$support_dir/monitor.zsh"
```

Render the LaunchAgents with paths for the current user:

```zsh
python3 - <<'PYTHON'
from pathlib import Path
import plistlib

home = Path.home()
replacements = {
    "__SUPPORT_DIR__": str(home / "Library/Application Support/mac-setup/services"),
    "__LOG_DIR__": str(home / "Library/Logs/mac-setup"),
}
for template in Path("launchagents").glob("*.plist.template"):
    data = plistlib.loads(template.read_bytes())
    for key, value in data.items():
        if isinstance(value, str):
            for old, new in replacements.items():
                value = value.replace(old, new)
            data[key] = value
        elif isinstance(value, list):
            for old, new in replacements.items():
                value = [item.replace(old, new) for item in value]
            data[key] = value
    target = home / "Library/LaunchAgents" / template.name.removesuffix(".template")
    target.write_bytes(plistlib.dumps(data))
PYTHON
```

Load or restart the two jobs:

```zsh
for label in com.samochreno.macbook-power-monitor com.samochreno.macbook-power-sleep-listener; do
  plist="$HOME/Library/LaunchAgents/$label.plist"
  plutil -lint "$plist"
  launchctl bootout "gui/$(id -u)/$label" 2>/dev/null || true
  launchctl bootstrap "gui/$(id -u)" "$plist"
done
```

Optionally install the general sender:

```zsh
mkdir -p "$HOME/.local/bin"
install -m 755 send-telegram "$HOME/.local/bin/send-telegram"
# Put ~/.local/bin on PATH if it is not there already.
send-telegram "ahoj zo scriptu"
```

## Inspect and troubleshoot

```zsh
launchctl print "gui/$(id -u)/com.samochreno.macbook-power-monitor"
launchctl print "gui/$(id -u)/com.samochreno.macbook-power-sleep-listener"
tail -n 50 "$HOME/Library/Logs/mac-setup/macbook-power-monitor.log"
tail -n 50 "$HOME/Library/Logs/mac-setup/macbook-power-sleep-listener.log"
pmset -g custom
```

The interval job can be loaded but idle between checks. To test the actual
flow: unplug and lock with the lid open, wait for one alert, unlock and verify
there is no duplicate, then connect power and check for 👍 on that message.
Test lid-close sleep separately. Telegram reactions need not generate a new
phone notification. Manually running `./monitor.zsh` can send a real alert and
uses a separate state file in the checkout, so prefer the installed copy.

For changes, edit `choose_message` for wording, `INACTIVE_SECONDS` for lock/idle
thresholds, the `battery_percent <= 10` condition for the battery threshold,
and `StartInterval` in the checker template for polling frequency.

## Checks without sending messages

```zsh
zsh -n monitor.zsh configure-telegram.zsh
xcrun clang -Wall -Wextra -Werror -fsyntax-only sleep-listener.c
python3 - <<'PYTHON'
from pathlib import Path
compile(Path("send-telegram").read_text(), "send-telegram", "exec")
PYTHON
```

No Telegram receiver, reply handling, Hermes integration, or Codex bridge is
implemented here.
