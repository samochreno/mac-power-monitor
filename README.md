# Mac power monitor

Local MacBook charging reminders delivered to Samuel's Telegram bot. No AI,
Codex automation, or always-on external server is involved.

## What it does

- Checks every 15 seconds through a macOS LaunchAgent.
- While unplugged, sends an alert after 30 seconds locked, or when battery is
  at or below 10% and the Mac is locked or idle for at least 30 seconds.
- Attempts an immediate alert before system sleep, including lid-close sleep.
  Message delivery has a four-second timeout.
- Reacts with 👍 to the latest alert when AC power returns.
- Keeps one unresolved alert until power is connected. Unlocking or waking does
  not reset it. A process lock prevents concurrent checks from duplicating it.
- Randomly selects one of ten casual Slovak messages for each of the three
  alert categories. These are static strings, not generated by a model.

## Ownership and files

This repository is the single source of truth for the monitor, C sleep listener,
LaunchAgent templates, Telegram setup script, and installer. The general-purpose
sender is maintained separately in
[send-telegram](https://github.com/samochreno/send-telegram).

Installed programs and `.state` live under
`~/Library/Application Support/mac-power-monitor/`. Logs live under
`~/Library/Logs/mac-power-monitor/`. The two LaunchAgents retain their labels:

- `com.samochreno.macbook-power-monitor` — checks every 15 seconds
- `com.samochreno.macbook-power-sleep-listener` — persistent IOKit listener

The `.state` file remembers the outstanding alert message ID and lock timestamp.
The adjacent `.lock` prevents concurrent checks. Neither belongs in Git.

## Sleep limitations

Nothing executes during full system sleep. The listener handles the brief
window before sleep and power-source events while the Mac can execute code.
USB-C connection may cause a DarkWake, but delivery during that window is not
guaranteed. Disconnecting power during deep sleep may not wake the Mac at all.

The recovered listener subscribes to power-source changes; it does **not** have
a `kIOMessageSystemHasPoweredOn` callback. The older chat described an explicit
wake callback, so its description is not identical to this later implementation.
Pre-sleep notifications apply to system sleep generally, not exclusively lid
closure, even though some message variations mention a closed lid.

## Requirements and credentials

macOS on a MacBook, Command Line Tools (`xcode-select --install`), and `jq`.
The monitor and setup look for `jq` at `/opt/homebrew/bin/jq`, then `/usr/bin/jq`.
Python 3 is needed for the installer.

Both monitor commands retrieve these Keychain items for the current username:

- `codex-power-monitor-telegram-token`
- `codex-power-monitor-telegram-chat-id`

Credentials are deliberately absent from this repository. Existing Keychain
items continue to work. To configure a new bot, privately create it through
Telegram's @BotFather, open its chat, press Start and send a message, then run:

```zsh
./configure-telegram.zsh
```

Token input is hidden. Setup chooses the last chat found in the bot's updates,
so use a dedicated bot and do not add it to other chats before setup.

## Install and manage

Run from this checkout after installing Command Line Tools and `jq`:

```bash
xcode-select --install
brew install jq
python3 ./manage.py install
python3 ./manage.py status
python3 ./manage.py audit
```

Install builds the listener before stopping services, then installs the monitor
and renders paths for the current user. Reinstalling preserves `.state`, logs,
and Keychain credentials. If loading a job fails, it restores previous plists
and installed programs and reloads previously loaded jobs.

To remove the jobs and executable programs:

```bash
python3 ./manage.py uninstall
```

Uninstall preserves alert state, logs, and Keychain credentials. To inspect logs:

```bash
tail -n 50 "$HOME/Library/Logs/mac-power-monitor/macbook-power-monitor.log"
tail -n 50 "$HOME/Library/Logs/mac-power-monitor/macbook-power-sleep-listener.log"
```

A loaded/idle interval job is normal between checks. Audit verifies plist paths,
loaded jobs, their last exit status, installed script parity, and listener presence
without invoking the monitor or reading credentials. Monitor execution and the
interactive Telegram setup can send real messages; use normal lock/charge events
for an end-to-end check when desired.

For changes, edit `choose_message` for wording, `INACTIVE_SECONDS` for lock/idle
thresholds, the `battery_percent <= 10` condition for the battery threshold,
and `StartInterval` in the checker template for polling frequency.

## Checks without sending messages

```zsh
zsh -n monitor.zsh configure-telegram.zsh
xcrun clang -Wall -Wextra -Werror -fsyntax-only sleep-listener.c
python3 - <<'PYTHON'
from pathlib import Path
compile(Path("manage.py").read_text(), "manage.py", "exec")
PYTHON
```

No Telegram receiver, reply handling, Hermes integration, or Codex bridge is
implemented here.
